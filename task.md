## Known Prototype Limitations (Not Bugs)

- JSON file storage — not suitable for concurrent writes; upgrade to DB for production
- Mock payment — no real charges; clearly marked DEMO
- Mock email — logs to console; integrate SendGrid/SES for production
- Mock OTA sync — channel adapters return mock data
- In-memory rate limiting — resets on serverless cold starts; use Redis for production
- data/ directory files will be ephemeral on Vercel serverless (use DB for production)
- data/room-types.json and data/settings.json MUST be committed to git before Vercel deployment
  (currently untracked — run: git add data/room-types.json data/settings.json)

## Phase 10: Production Deployment Steps (REQUIRED before going live)

- [ ] Run: `git add .` (stage all untracked booking-system files)
- [ ] Run: `git commit -m "feat: Add complete booking system"`
- [ ] In Vercel Dashboard → Settings → Environment Variables, set:
  - AUTH_JWT_SECRET=<64-char random hex> (REQUIRED — generated via: node -e "console.log(require('crypto').randomBytes(64).toString('hex'))")
  - NODE_ENV=production
  - AUTH_SESSION_DURATION=8h (optional, default)
- [ ] Deploy to Vercel: `vercel --prod` or push to main branch
- [ ] After deploy: Run `node scripts/seed.js` locally, then manually upload data/users.json via a secure channel OR use the API setup endpoint
